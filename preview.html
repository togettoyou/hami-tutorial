1. 四种旁注

普通旁注

节点用量是算出来的：静态清单加上本地缓存里所有已调度 Pod 的分配值。

补充说明

两种相反的策略靠同一个 Less 反转实现。

需要注意

节点基础分不支持自定义权重，只有卡级打分支持。

容易踩的坑

DeviceUsage 是会被就地修改的，打分前必须 DeepCopy()， 否则一个节点的试算会污染另一个节点。

2. 代码块

func fitInDevices(node *NodeUsage, requests device.ContainerDeviceRequests) (bool, string) {
	for index := range node.Devices.DeviceLists {
		node.Devices.DeviceLists[index].ComputeScore(requests, weights)
	}
	for _, k := range requests {
		sort.Sort(node.Devices)
		devPlugin, ok := device.GetDevices()[k.Type]
		if !ok {
			return false, "Device type not found"
		}
		fit, tmpDevs, reason := devPlugin.Fit(typeDevices, k, pod, nodeInfo, devinput)
		if !fit {
			return false, reason
		}
	}
	return true, ""
}

3. 表格

策略排序（升序）末尾是谁，就优先选谁
binpack分数 低 → 高分数最高，也就是最满的卡，把碎片塞满
spread分数 高 → 低分数最低，也就是最空的卡，负载摊开
mutex已用份数 多 → 少已用份数最少，也就是全空闲的卡
